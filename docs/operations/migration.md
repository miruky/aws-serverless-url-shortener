# 旧版からの移行

この変更は、既存のAWSリソースを調査・変更・削除していません。
`template.yaml` と `pipeline.yaml` は初期版の記録です。新版は `product.yaml` を使います。

## 先に止めるもの

既存CodePipelineを使っている場合、GitHubへ新版を送る前に自動デプロイを一時停止してください。
旧パイプラインはLambda成果物の参照・CloudFormation権限・パラメータ引渡しが不十分で、新版の認証や管理画面も配置しません。
新版のGitHub Actionsは検査と配布物の生成だけを行い、AWSを自動変更しません。`buildspec.yml` もビルド専用で、旧Deployステージとは互換性がありません。

## 互換性の変更

- 管理APIが認証必須になる。既存の匿名クライアントは更新が必要
- 301から302へ変更する。既にブラウザ等へ保存された旧301をサーバーから消すことはできない
- 作成時のID衝突では上書きしない
- 一覧は停止済みを含み、cursorによる継続読込を行う
- 不正なlimitを既定値へ置き換えず400にする
- URLの国際化部分を正規化する。元の文字表現をそのまま保存する契約ではない
- 管理レスポンスにtitle、version、期限等を追加する

以前のshort_id・original_url・created_at・click_count・is_activeは読込可能です。
追加フィールドのないレコードも扱います。実際の旧データの品質は別途確認してください。

## 安全な切替の判断

新しく生成した物理名を、既存スタックへそのまま投入しないでください。テーブルやユーザープール等の置換につながります。
既存のテーブル名、利用者、短縮リンクの公開基点、呼出元、バックアップ、CloudFormation管理状態を確認してから移行方法を選びます。
既存の名前が現在の命名規則と異なることだけを理由に変更しません。

推奨する受入順序は、新しい隔離環境で配置・認証・転送・停止・復旧を確認し、データのコピーまたは既存テーブルの継続利用を個別に設計することです。
IDは維持します。新規IDへ置き換えると既存の共有リンクが失効します。

テーブルの移行やDNS切替を自動化したスクリプトは、この版には含めません。無停止移行や既存本番環境との互換性を検証済みとはしていません。
