# セキュリティとプライバシー

## 信頼境界

この製品は一つの管理領域を招待された管理者で共有します。Cognitoのセルフ登録を無効にし、管理APIの署名・発行元・クライアントの検証はAPI Gatewayへ任せます。
ハンドラーは検証済みの `sub` を要求します。直接LambdaをinvokeできるIAM権限は信頼された運用者だけに与えてください。
別のHTTPサーバーへ移植する際、利用者が送ったJSONを「検証済みclaims」として渡してはいけません。

Cognitoは公開クライアント、認可コードとPKCE、state、nonceを使います。暗黙的フローやクライアントシークレットは使いません。
IDトークンは画面のメモリだけに保持し、refresh tokenは保存しません。再読込や有効期限切れでは再ログインが必要です。
ログアウトは画面のトークンとCognitoのログインセッションを終了しますが、既に取得されたJWTの即時失効を保証しません。トークンの有効期間は15分です。
管理者にはTOTPによるMFAを要求します。アカウントの復旧・退職時の権限廃止は運用手順として別途確認してください。

## リンクとアクセス

転送先のサーバーへHTTPリクエストを送る機能はありません。URLプレビューのための取得も行いません。
入力検査はURLの形式を扱うもので、マルウェアやフィッシング判定ではありません。一般公開SaaSにするには通報、審査、利用者単位の制限、テナント分離が必要です。

IDは乱数で作り、条件付き書込で既存リンクを上書きしません。IDの推測困難性をアクセス制御の代わりにはできません。
元のコンテンツが秘密である場合は、リンク先でも認証を行ってください。

カウントはGETの転送処理回数です。IPアドレス、ユーザーエージェント、リファラーをアプリのレコードへ保存しません。
AWSの認証・監査サービスが扱うデータは別です。管理者のメールアドレス等はCognitoで扱います。

## 保存と削除

DynamoDBには元URL、タイトル、ID、作成時刻、期限、公開状態、version、合計カウントを保存します。
公開停止と期限切れでは削除しません。古い短縮IDが別の内容へ割り当てられるのを防ぐためです。
個人情報の削除が必要な場合は、転送先情報の除去とID予約の維持を分けた移行を設計してください。現版に利用者向けの消去操作はありません。

テーブルはPITRを有効にし、スタック削除や置換時も保持します。ログは標準30日です。Retainされたテーブル・ログ・Cognito・配布バケットはスタック削除後も残るため、費用と削除判断を別に管理してください。
PITRの設定だけでは復旧できた証拠になりません。復元先への切替を実AWSで演習してください。

## 端末内のデモ

デモはループバックのみで待ち受け、HostとOriginを検査し、起動ごとの一時トークンで管理APIを保護します。
AWS環境変数をダミー値へ差し替え、Motoのプロセスメモリ内で処理します。公開サーバーとして使う設計ではありません。
デモの設定が返す一時トークンを本番の認証に流用しないでください。

## 検証と限界

構文、テンプレート規則、認証ガード、入力境界、条件付き更新を自動検査します。
実際のCognitoログイン、IAMの実効権限、スロットリング、障害復旧、負荷、AWSアカウント側の監査設定は未検証です。
独自ドメインとWAF、通報窓口、コスト通知、APIアクセスログの設定は運用環境に合わせる必要があります。
